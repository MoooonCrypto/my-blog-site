  根本原因の特定のために確認すべき項目

  開発環境で動作しているのに本番環境で動作しないのは、環境設定の問題である可能性が高いです。以下を順番に確認してください：

  1. Vercel 環境変数の確認

  Vercel ダッシュボードで以下を確認：
  1. プロジェクトの Settings → Environment Variables
  2. 以下の環境変数が正しく設定されているか確認：
    - NEXT_PUBLIC_SUPABASE_URL
    - NEXT_PUBLIC_SUPABASE_ANON_KEY
  3. 重要: これらの環境変数が Production 環境に設定されているか確認
  4. 値が正しいか（Supabase ダッシュボードの値と一致しているか）

  2. Supabase プロジェクト設定の確認

  Supabase ダッシュボードで以下を確認：
  1. Project Settings → API
    - Project URL が Vercel の環境変数と一致しているか
    - anon / public キーが一致しているか
  2. Authentication → URL Configuration
    - Site URL: 本番環境のURL（例: https://yourdomain.com）
    - Redirect URLs: 本番環境のURLが許可されているか
        - https://yourdomain.com/admin/dashboard など
  3. Authentication → Providers → Email
    - Email provider が有効になっているか
    - Confirm email が無効になっているか（テスト用の場合）
  4. Authentication → Users
    - 管理者ユーザーが実際に存在するか
    - そのユーザーのメールアドレスとパスワードを確認

  3. Vercel ビルドログの確認

  Vercel ダッシュボード → Deployments → 最新のデプロイ → ビルドログ
  - エラーや警告が出ていないか
  - 環境変数が読み込まれているか（ログに表示される場合）

  4. Vercel Function Logs の確認

  Vercel ダッシュボード → Deployments → 最新のデプロイ → Function Logs
  - ログインを試みた時のログを確認
  - middleware が実行されているか
  - エラーが出ているか

  5. ブラウザの開発者ツールで確認

  本番環境でログインを試みる際：
  1. F12 で開発者ツールを開く
  
  2. Network タブ:
    - /api/auth/... へのリクエストが送信されているか
    - レスポンスのステータスコード
    - Set-Cookie ヘッダーが返ってきているか
  3. Application タブ → Cookies:
    - Supabase の認証 Cookie が設定されているか
    - Cookie の Domain、Path、SameSite 属性を確認
  4. Console タブ:
    - エラーメッセージが出ていないか

  6. 最も可能性が高い原因

  以下の順で確認してください：

  1. Vercel の環境変数が設定されていない ← 最も可能性が高い
  2. Supabase の Site URL / Redirect URLs が本番環境に対応していない
  3. Cookie の SameSite 属性の問題（本番が https、開発が http の場合）
  4. Vercel の Edge Middleware のキャッシュ問題
